# 通用候选方案交付

Analyst 通过带类型的 `validate_plan(analysis: AnalysisPayload)` 提交完整方案。单源和跨源使用同一套字段与结构校验。输入直接填写方案，不嵌套 `plan` 或 `payload`。

成功返回 `candidate_id` 和校验结果。最终 `AgentSubmission.payload` 只提交 `{"candidate_id":"..."}`，服务端复制已经保存的方案并再次验证，避免模型重写时遗漏条件。引用不得混入字段覆盖。历史直接提交完整方案的协议仍兼容，并走完整校验；新提示词优先使用候选引用。

候选仅在当前运行的当前分析阶段内有效，不跨会话或跨复核修订复用；绑定当前问题、本体、数据权限和确认需求。阶段切换清除候选。服务重启后不恢复候选 ID，必须重新校验。候选不是审批，也不能绕过 Reviewer、SQL 门禁或执行权限。

跨源错误附带 `source_steps[index](name).query`，缺少输出字段时明确区分 `fields`、`metrics` 和 `calculations`，不把程序结构错误泛化为要求用户补充业务需求。同一候选内容和校验错误重复三次时终止无进展修订，记录 `agent.validation.stalled`；不同方案仍受原有模型轮次、工具次数和总时限约束。

本机制不包含行业词汇、业务对象名称或业务规则。业务事实来自当前域配置、本体、用户确认和证据。不改变模型的推理预算，也不新增数据查询后的任意 AI 文本分析执行能力。
