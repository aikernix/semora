# 离线建模扩展开发文档

本文件描述拟实现的接口、数据模型和任务约定。架构与业务规则见 [架构设计](architecture.md)。

## 文件组织

```text
extensions/offline-modeling/
  backend/
    documents/
    ddl/
    catalog/
    modeling/
    api/
  frontend/
  migrations/
  tests/
  compose.yml
  README.md
```

`documents` 的输入和输出使用独立契约。目录 ID、DDL 方言、关系生效策略等放在调用侧。允许文档案例单独携带原文提供的方言线索。

离线数据源表单必须上传一份 DDL，文档允许零份或多份。后端收到缺失、解析失败或无法形成有效表目录的 DDL 时，返回具体导入错误。文档抽取组件可独立调用，离线产品入口以一次导入接收整套文件。导入完成后冻结资料和目录。

## 导入、切块与 Agent

| 格式 | 首版处理 | 保留位置 |
| --- | --- | --- |
| XLSX | 识别有效区域、多级表头和合并单元格，模型给列映射，程序批量提取 | Sheet 和单元格范围 |
| DOCX | 读取标题、段落与表格，按章节和记录聚合 | 标题路径、段落或表格行 |
| TXT / SQL | 识别条目、完整 SQL 和相邻业务说明 | 行区间 |
| DDL | 按方言解析表、字段、键、索引、注释和可解析视图，记录未支持的语句 | 语句位置 |
| ER 图 / PDF | 后续增加图像或版面适配器，保留实体、端点和字段证据 | 页码和图中区域 |

导入编排先建立整份文档的可读区域清单，再逐块处理所有有效区域。跨页表格携带列头和所属表，长 SQL 分片沿用同一案例标识。首次覆盖以区域处理记录为准。导入进度按已落库分块计算，区分已抽取、无相关内容、待消歧及技术失败。

程序负责 SQL AST 解析、格式明确的表格读取、引用检查与去重。Agent 负责版式识别、非结构化语义抽取及必要消歧。工具可按块 ID 回读原文或相邻块、按表字段检索、查询已抽取事实。设置每块上下文、并发、工具步数及重试预算。模型输出必须关联真实出处。文件中的文字作为输入资料，DDL 和历史 SQL 仅解析。

## 大型 DDL 的语句切分与表目录组装

1. **流式读取，按语句交给解析器。** 文件按字节块读取，增量解码器和方言扫描器跨块保存状态，包括字符串、转义、引号标识符、注释、括号和当前语句终止规则。例如注释、默认值字符串或带引号标识符中的分号都不能作为切点。当前实现 MySQL、PostgreSQL、Oracle 和 SQL Server 的受支持导出格式，用包含跨块引号、MySQL 分隔符指令和 PostgreSQL dollar-quoted 内容的样例验证边界。无法可靠确定边界的语句或导出格式，返回位置明确的诊断。
2. **完整语句是解析单位，表是组装单位。** 完整 `CREATE TABLE` 作为一个语句解析，记录字节范围和起始行。临时文件可承载超出内存缓冲区的语句，解析前仍受单语句资源上限约束。超限时报错并指出位置，避免把半条语句解析成半张表。仅提取支持的结构语句，按文件顺序处理会影响对象定义的语句。数据插入等内容跳过并计数，无法应用的结构变更显式报告。
3. **把分散定义归并到同一张表。** 维护方言对应的默认数据库或 Schema 上下文，按带命名空间的物理标识暂存表、字段、约束、索引和注释。语句可分批落库，复合键字段顺序和每项定义的位置一起保存。文件读完后补解析指向后续表的外键引用，再校验两端字段；缺失目标保留为未解析引用。无法可靠恢复的结构变更阻止本次激活。
4. **目录就绪后才按表组织模型输入。** 标准表目录与在线扫描使用同一输出契约，保留来源及未知项。普通表按表数和上下文预算组批；超宽表按字段分片，保留稳定表 ID、字段范围和完整键/约束引用。分片只是同一张表的部分视图。涉及未读字段的映射需补齐资料再判定，不能把分片当独立表或完整覆盖。DDL 的结构解析由程序完成，模型读取的是目录投影。

恢复以文件哈希、方言配置和最近已持久化的完整语句边界为准。检查点一并记录该位置的命名空间和分隔符状态，避免续跑时归错 Schema 或切错语句。MySQL 和 PostgreSQL 各选一套测试结构，对照同结构的在线扫描结果，核验表字段、标识符、排序后的目录及有序约束，而非比较原始文本。

## 存储设计

首版用扩展自己的 SQLite 文件持久化目录、导入任务和关系，原文件独立保存在同一扩展数据卷。后续需要多实例或向量召回时再评估 PostgreSQL。

| 记录 | 主要字段 |
| --- | --- |
| 文档版本 | 项目或资料库范围、文件哈希、解析版本、文件存储引用、状态 |
| 文档块 | 文档版本、块 ID、父块与前后块、位置、正文、内容哈希 |
| 抽取事实 | 类型、原始对象引用、结构化内容、出处列表、抽取版本 |
| 查询案例 | 业务原话、SQL、表字段索引、指标及粒度、过滤、物理 JOIN、出处 |
| 目录快照及绑定 | 来源版本、物理对象、绑定结果、冲突、输入指纹 |
| 关系及本体版本 | 两端字段、有序键、附加条件、基数、状态、生效依据和出处 |
| 导入与分析任务 | 阶段、分块检查点、错误和输出目录或关系版本 |

精确检索优先使用已归一的表字段索引、SQL AST 和关键词。原文回读使用块 ID 和位置。语义召回作为可选增强，使用 pgvector 索引业务说明、案例问题和口径摘要，结合关键词候选和对象范围重排。向量按块内容哈希与嵌入模型版本维护。关联条件与 SQL 原文从结构记录和原始块读取。

## 接口草案

以下路径为扩展内部版本化协议，命名可在首阶段确认。

| 接口 | 输入与输出 |
| --- | --- |
| `POST /v1/documents/imports` | 多文件和资料库 ID，返回导入任务 ID |
| `GET /v1/documents/imports/{id}` | 返回进度、失败区域及抽取产物引用 |
| `GET /v1/documents/blocks/{id}` | 返回原文、前后块及来源位置 |
| `POST /v1/evidence/search` | 按表字段、问题和事实类型查询，返回带出处的证据 |
| `POST /v1/imports` | 提交目标数据库配置、必传 DDL 和可选文档，创建一次性导入任务 |
| `POST /v1/imports/{id}/confirm` | 确认初次导入预览，原子创建虚拟数据源并冻结输入 |
| `POST /v1/projects/{id}/analyses` | 基于固定目录与证据版本发起关系分析 |
| `POST /v1/projects/{id}/relations/{id}/decision` | 审核推断关系，记录操作者及采用依据 |
| `POST /v1/projects/{id}/ontology/publish` | 校验并发布扩展快照，返回快照 ID |
| 关系管理接口 | 查看、新增、编辑、停用和恢复关联，校验两端字段、完整条件和基数，更新生效关系版本 |

文档接口支持按资料库权限调用，结构绑定由项目服务完成。未来在线适配可以提交扫描目录、读取声明关系和相关案例。绑定缓存由目录及文档版本共同决定，文档抽取和向量索引可跨绑定复用。

## 状态、更新与交付

- 文档块按文件哈希、块标识和抽取版本幂等写入。恢复时读取已完成分块，只重跑本次导入失败的分块，继续使用同一批文件。
- 导入确认事务固定文件、目录及方言配置，同一任务重复确认返回同一数据源。导入完成后的接口拒绝替换文件、补传文档或修改物理目录。用户可用新资料创建另一个数据源。
- 连接状态、文档抽取状态、关系生效依据、数据验证状态分别表达。明确声明关系自动生效与导入冲突处理是两个步骤。
- 人工调整只写关系层。编辑或停用声明关系保留原文件出处，并记录人工决定。重新分析沿用冻结资料，保留人工修改和停用状态。关系校验及生效版本更新在同一事务完成，失败保留上一版关系。
