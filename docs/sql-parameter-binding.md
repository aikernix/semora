# SQL 参数绑定边界

本次修复公共查询编译层中 HAVING、条件聚合的具名占位符渲染。与业务域、本体对象名称、数据源账号无关。

编译阶段保留 SQLGlot 的参数 AST 节点及独立参数字典。在输出表达式时，仅转换参数节点为明确的参数风格，不全局替换冒号，不把参数值拼进 SQL。MySQL/PyMySQL 与 PostgreSQL/psycopg 目前共同使用 `pyformat`：`%(name)s`。

`render_bound_expression` 将 SQL 方言与参数风格分开：`dialect` 控制 SQL 语法，`paramstyle` 控制具名占位符。当前实现 `pyformat` 和 `named` 渲染；其他风格明确拒绝，不能仅改数据库类型就声称支持新驱动。`named` 渲染测试通过不代表某一数据库产品适配完成。

后续接入任何数据库（包括国产数据库）需按具体产品版本、兼容模式和 Python 驱动补齐独立适配：

- SQL 方言及语义规划能力；聚合、日期、精度、分页等行为。
- 驱动参数风格与类型绑定，重复参数、NULL、日期、Unicode、数值精度。
- 只读事务、超时、取消、元数据扫描及成本估算。
- 单源、跨源执行及现有权限检查的真实数据库回归。

不能假设具备某种兼容模式就完全兼容已有适配器。未适配的数据源继续明确拒绝，不退化为 SQL 字符串拼值。本次不新增数据源类型，也不改变审批或访问权限。

回归覆盖直接编译、真实 Wren 展开、MySQL 转译、多 HAVING 参数、条件聚合、字符串冒号和类型转换。另使用现有真实 PostgreSQL/MySQL 驱动对纯常量只读聚合执行绑定验证，不创建源表或视图。
