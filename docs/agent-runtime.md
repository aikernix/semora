# Semora Agent 运行与协作

## 运行边界

LangChain 1.4.8 `create_agent` 提供模型—工具—观察循环，原有 OpenAI 兼容配置通过 `ToolCallingModel` 适配，无新增模型密钥配置或服务。LangGraph 保留任务生命周期、用户输入中断和 PostgreSQL Checkpointer。全部 Agent 在现有 API 容器内运行。

- Analyst：唯一会话分析负责人，可根据上下文主动选择 Wiki 搜索、Wiki 关联页、原文溯源、本体对象、关系路径、扫描结构和方案校验。用户补充后仍可重新检索。
- Reviewer：单独构建上下文，不读取 Analyst 消息记忆。只能核验公开产物、本体、Schema 和已收集证据，没有执行 SQL、修改配置或调用 Analyst 的工具。
- 知识库、本体、编译器和 Executor 是工具或确定性服务，不拆成更多 Agent。

每轮模型返回后只执行一个工具动作，再把观察交给模型选择下一步。请求显式关闭 parallel_tool_calls；供应商仍返回多个动作时，仅执行一个非终结动作，其余由后续轮次重新选择。search_wiki 一次只接受一个短关键词、别名或表名，多词拼接会返回修正提示，不自动批量查询。关键词按字面量转义，避免被上游误当作复杂正则。零命中时提示模型换短词/别名继续，命中后先阅读相关页面再针对证据缺口继续研究；返回条数达到8时明确提示只是本次上限。

问数和知识库测试入口均保留知识库范围限制。只绑定一个知识库时，模型可省略ID，由程序使用唯一绑定；明确提供其他ID时仍拒绝访问。绑定多个库时，缺少或无效ID会返回允许的ID列表，要求模型重新选择，不默认选择第一个。知识库页面的研究测试会把参数错误交回模型纠正，连续3次范围错误才终止，避免把漏填ID直接误报为实际访问了其他知识库。

Agent 交付使用 `AgentSubmission.payload`。Analyst 交付需求草稿与澄清或查询计划；Reviewer 返回 approved/revise/rejected、issues、rationale。所有产物重新经过现有契约和本体白名单校验，错误会交回 Agent 最多修正 3 次；不会把模型声明当作权限或执行凭据。

模型只返回普通文本、未调用交付工具时，保留已取得的工具观察，要求重新通过 AgentSubmission 交付，并在下一轮显式指定该工具。最多3次交付尝试，仍受总时间/模型轮次上限约束。持续不合规时准确报告“结构化交付失败”，不把已经成功调用工具的模型直接判定为不支持工具调用；输出被长度上限截断时单独报告。

## 反馈与确认

### 阶段式 QueryPlan（v2）

stages描述源对象按完整关联键预聚合，关联阶段结果后仅按dimensions最终汇总。每阶段包含name、label、source、group_by、measures、filters和join_type（默认left）。阶段指标用阶段名.指标名引用；参数仍绑定传递。所有阶段编译为同一条WITH/CTE SQL，经固定版本Wren展开，再由Executor执行一次；不在Python分多次查库拼接。

编译前的确定性检查阻止非分组明细混入汇总、关联放大、阶段分组键未被关联等值列完整覆盖、未知基数无法证明安全、已聚合明细字段继续被引用、阶段名冲突及不连续关系路径。关联基数依据已发布本体声明与键映射，不把模型说明当成基数证明。阶段AVG自动携带SUM和COUNT做加权合并；不能相加局部COUNT DISTINCT替代全局去重。空源、零行和NULL结果正常处理。阶段结构与计算定义进入不可变需求哈希；改变它们必须重新确认，旧审批失效。敏感源字段的权限与结果敏感标记继续传播。

首版每个源对象最多一个预聚合阶段，最多8个独立阶段；阶段只读取自己的源对象，不支持阶段再读取另一阶段或自由SQL表达式。不能安全表达的计划明确拒绝，不降级为有放大风险的直接JOIN。涉及一对多的旧v1计划也必须通过结构门禁。

### Reviewer预算与输入

所有角色的read_object只返回字段、业务说明及完整直接关系目录，去掉导入工作簿的重复sourceEvidence等元数据；find_relation_path返回选定路径与候选角色的完整关联条件。字段、枚举、单位、敏感标记、默认过滤及执行表达式不截断。用户补充时，旧工具消息按同一规则精简，仅修改发送给模型的副本，不改写本体或审计历史。跨表维度须在源对象按关联键预聚合后关联，不能放入单源stage的group_by。

每次方案预检、执行前复核、结果复核分别最多4轮模型调用、3次只读工具调用；最后一轮强制结构化交付。上下文携带确定性结构检查、实际用到的字段和关系目录，不携带全库结构和重复原始产物；重复同参数工具返回“已有观察未变”，不追加整份重复数据。已提供SQL和方案时不再暴露重复读取它们的inspect_artifacts工具。结果复核最多携带20行脱敏样本，并标记样本数。Reviewer重点检查用户业务目标、口径、单位和范围；不能绕过结构门禁，超时或证据不足不自动通过。

角色提示词适用于任意业务域，不内置行业对象或口径。Analyst、方案预检和执行前后 Reviewer 的上下文均携带 business_domain（domain、name、description），再结合当前发布本体、用户确认和实际证据解释业务含义。知识研究、候选抽取及单次JSON兼容分支使用相同的行业中立原则。无模型兼容路径不再硬编码行业澄清选项；结果摘要的标签和百分比格式来自本体指标及本次计算定义。银行仅作为当前配置的演示业务域。

执行字段必须引用本体的对象name.属性name，不能直接使用物理表名、column或中文label。read_object显式返回field_refs；无效字段校验反馈具体的方案位置、名称和受限候选，候选不会自动映射或放行。未发布指标会列出可用指标并说明临时聚合必须先在calculations定义。每次校验失败（包括最后一次）均记录公开诊断，不记录原始模型隐藏推理。

本体工作室分别展示草稿与已发布版本及对象/关系数量，查询工作台显示该Run实际绑定的版本。保存草稿不改变查询使用的快照，发布后仅新查询使用最新版本；历史Run不自动迁移。

Analyst 的可执行方案在展示用户确认前，先由独立 Reviewer 做完整性预检，检查目标覆盖、条件落地、对象关联和一对多聚合风险。预检最多进行3次；缺少业务信息时由 Analyst 提出澄清，不擅自补口径。明确写入说明的已发布字段标量比较必须进入 filters；歧义、否定和复杂表达式交给语义预检，规则不猜测解析。

执行前 Reviewer 的 revise 进入 LangGraph revise 节点，由 Analyst 根据意见重新调用工具、调整方案或请求补充。若只是补齐用户已确认的结构化筛选或说明中的明确条件，且指标、计算、维度、输出、时间、粒度、关系路径、数据范围及假设均保持一致，则保留不可变需求版本，在内部重新编译、门禁和独立复核。新增敏感筛选字段不走内部修复捷径。其他语义变化必须重新确认。所有修订都会使旧 SQL、门禁、审批和结果失效；rejected 直接终止。确定性门禁不允许 Agent 覆盖。最多修订3轮；提交相同执行方案时提前停止。执行后复核失败停止发布解释，不自动重复查询。

修订上下文明确包含被退回的 QueryPlan 和 SQL。若候选方案只修改说明、假设或分析文字，执行字段没有变化，则校验退回 Agent，不让同一执行计划反复进入用户确认。Reviewer 同时接收原始需求单和已确认事实，核对时间、范围或指标是否遗漏。

页面将待确认/审批/错误放在优先位置。只有门禁和独立 Reviewer 均通过的 SQL 才进入“当前 SQL”。尚未完成复核、被退回和被拒绝的版本只进入默认折叠的“历史 SQL 与草稿”。安全门禁通过不会被误标为独立复核通过。协作记录、知识研究、历史口径和阶段时间线默认折叠；草稿从原始 sql.ready/review.completed 事件恢复只读展示，不恢复执行授权。SSE 使用事件序号去重，快照刷新串行处理，并阻止事件数量较旧的快照覆盖较新状态；折叠和展示不会改写审计事件。

用户确认前不执行数据库查询，也不提前生成 SQL；工具 validate_plan 校验本体约束和明确条件的执行落地。正式 SQL 仍由 Wren 规划器生成，并由独立执行器估算和只读执行。

筛选支持is_null/is_not_null，对应SQL的IS NULL/IS NOT NULL，无需绑定空值参数；eq/ne显式JSON null会规范为相应空值运算，禁止生成“= NULL”。主查询、阶段筛选和条件聚合均支持。说明与analysis_steps中的明确字段比较或空值条件会在预检前核对是否已进入执行字段；有歧义的口径仍由Analyst向用户确认。自动修订耗尽时，顶部错误只返回简短结果，详细校验与Reviewer意见保留在原始事件和审计中，不复制到失败提示。

## 预算、恢复与显示

失败后同一会话发送消息，默认创建关联上一尝试的续聊记录，携带原需求、已确认补充、最后候选方案和复核意见；不复制原始模型对话、SQL、审批、结果或执行授权。回答在调用模型前持久化，连续失败仍保留。旧记录只从框架构造的Human补充和AgentSubmission结构化字段恢复，不将模型文本当作用户确认。任务轮次跨尝试累计，单次调用预算独立。页面提供“继续当前需求/新需求”；新需求不继承旧需求单或失败上下文。权限变化禁用接续；本体重新绑定，版本变化时重新核验，证据仅在绑定相同且原始年龄不超过15分钟时复用，不因反复重试延长缓存年龄。

每次 Agent 运行最多 12 次工具调用、16 次模型调用，总时间默认 900 秒，可通过 AGENT_TIMEOUT_SECONDS 配置。达到上限返回明确错误。Wiki 页面和文档必须来自绑定知识库以及已经发现的链接或引用；拒绝任意路径访问。工具错误不携带数据库 URL、认证头或密钥。

达到总时限会发布agent.analysis.timeout，包含已发起的模型轮数、工具次数、请求超时数和重试数，不再笼统要求用户缩小需求；原有300秒单次请求与900秒总预算保持不变。

单次模型请求默认超时为 300 秒（5 分钟），可通过 LLM_TIMEOUT_SECONDS 覆盖；Agent 多轮分析总预算默认 900 秒（15 分钟），避免原有 240 秒的外层时限提前中断模型请求。浏览器无需等待一个长 HTTP 请求，后台失败会以 run.failed 事件返回。

模型读取响应超时默认重试1次（LLM_REQUEST_RETRIES，可配置0至2次），重试只重发模型请求，不执行或重放业务工具，仍受Agent总时限约束。认证、HTTP拒绝、其他网络错误和响应结构错误分类报告，不再统一归因于不支持工具调用。公开审计记录请求尝试次数、消息数、请求字节数和耗时，不保存请求正文、密钥或供应商隐藏推理。表为空和查询零行是正常结果，不设置数据为空的阻断规则。

运行记忆存入 Run 的内部 agent_memory；持久化时显式写入，API/SSE 序列化时排除。适配器不转发或保存供应商 reasoning_content。页面展示 agent.model.started、agent.tool.started/completed、agent.validation.failed、review.revision.required 等公开操作事件。

公开过程记录展示每次工具调用的核验目标、受限查询参数，以及检索词/命中页面、引用摘录、对象字段数量、关联路径、校验结论等可核验观察；不展示完整模型消息或隐藏思维链。轮次按照同一Run已持久化的模型调用事件连续累计，跨用户补充、复核、修订和进程恢复不重置；另标阶段和角色累计轮次。运行实例内部的局部计数只用于每次调用预算。页面同时按事件顺序计算展示轮次，以兼容旧历史记录中的局部编号，不改写原始审计事件。

补充命令先保存 pending_alignment，再立即返回 HTTP 202；后台恢复 LangGraph 任务，SSE 持续送出进度并在新澄清/完成/失败时收尾。重复提交在状态检查处阻止。若进程重启，已登记的补充命令在 Checkpointer 配置后恢复；已终结任务不重新执行。

## 验证范围

回归测试覆盖工具结果进入下一轮、跨澄清保留上下文、无效计划重做、工具预算、Wiki 发现链和跨库拦截、Reviewer 上下文隔离、修订后重新确认、三轮修订终止、异步补充和重复提交、模型工具兼容性测试。实际模型可用性和复杂聚合能力仍取决于模型服务与已发布本体的完整性。
