# 任务交接与记忆隔离：第一批实施

本文记录第一批任务交接实施，复用现有两个模型角色和服务。后续 QueryIntent 技术规划迁移已部署，当前范围与验收见 [业务意图与程序规划](query-intent-planning.md)。

## 已接入

- Owner 在 Analyst、方案预检、执行复核、结果复核前创建独立任务包，包含任务 ID、操作目标、输入修订哈希、权限与本体绑定、确认事实引用、验收要求和请求大小限制。
- 分派前检查目标、用户确认、完整选项说明、本体字段与关系端点；执行复核必须具备全部源产物，结果复核必须具备结果。缺核心资料时停止该次分派，返回技术缺口；辅助知识无命中不阻断。
- 当前完整语义定义和关系保留，物理扫描副本从初始模型包移除，仅保留扫描状态。明确请求物理结构的工具仍可读取相关扫描结构。
- Analyst 每次新任务使用新消息段；历史任务保留在服务端，不重放整个旧工具对话。未解决的业务问题、确认事实、历史有效执行条件和当前修订要求通过任务包交接。
- Reviewer 不接收 Analyst 私有对话或整份任务记忆。跨源最终 SQL 已存在于步骤产物时，根 SQL 使用同包引用，避免重复复制。当前精确执行条件仍显式提供。
- 相同用户事实只在确认语义完整覆盖时去重；未覆盖的历史事实和用户原话仍保留。有效日期、筛选、排序与完整选项含义不会通过自由摘要替换。
- 每个模型请求默认限制为 128 KiB（包含提示词与工具 Schema），同时受 `AGENT_CONTEXT_MAX_BYTES` 的更小上限约束。可分别配置 `AGENT_ANALYST_CONTEXT_MAX_BYTES`、`AGENT_REVIEWER_CONTEXT_MAX_BYTES`。不把字节当作精确 token；超过上限明确停止，不截断关键条件。
- JSON 单次调用也受全局上下文大小限制，避免说明或信息判断绕过预算。可选模型说明失败时保留已核验的查询结果，返回实际行数和明确提示，不将已成功执行的查询重新标成执行失败。
- 结果 Reviewer 与最终说明均接收各步骤真实执行计数，不接收中间原始键列表；结果任务缺少必要步骤计数时不分派，不能从最终行数推断前置记录不足。
- 模型请求前、响应后、工具前后及结构化交付时验证输入修订。需求、确认答案、权限、本体或当前执行计划变化，或者任务已取消，旧结果不会继续调用工具或覆盖当前状态。该保护针对当前单 API 进程；多副本数据库原子提交仍需另行实现。
- 审计事件关联 task_id，并记录角色、操作、输入版本、投影前后字节和事实数量。仅保存最近任务交接元数据，完整业务事实继续由原有存储持有。

## 边界

就绪检查不能证明自然语言已被正确理解，也不能代替 Reviewer。底层模型仍可能给出错误方案，所有结构门禁与审批照常生效。当前 Agent 仍输出兼容 QueryPlan；下一批应将物理源拆步、传键与预聚合生成迁入确定性规划器，并定义正式 QueryIntent。

## 验证

新增测试覆盖：完整口径与高精度值保留、未覆盖历史信息保留、辅助知识缺失、关系端点和产物缺失、跨角色私有消息隔离、输入和权限变更、取消、模型迟到响应禁止调用工具、Owner 丢弃过时结果，以及角色预算包含工具 Schema。

真实联调使用独立验收会话，基于已确认口径修改数量，检查新任务的选择数量、重复实体规则、汇总方式及排序，并对照审计事件统计实际上下文大小。验收结果保存于本地 `artifacts/source-planning/`，不得将单次通过当作产品整体可交付证明。

2026-11-06 联调：数量 10→5→10→5 的连续修改中，三次新查询均完成，分别选择 5、10、5 条，返回 3、8、3 条匹配结果，选取键范围与降序核验通过。第一轮 Analyst 正文由 68,475 字节降至 48,553 字节，完整保留 4 项确认；这是任务正文大小，不等于整个 HTTP 请求大小。两轮初测发现 Reviewer 缺少分步计数而误解最终行数，补齐执行收据后第三轮明确区分首步 5 条与最终 3 条。历史错误结论保留审计记录，不追改成成功证据。
