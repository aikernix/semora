# 分步跨数据源查询实施与验收

目标：在codex/cross-source-query分支支持不同实例A→B→C的分步问数。用户只回答实质性业务歧义；口径明确后，经Reviewer和确定性门禁通过直接执行、展示SQL、结果和说明。

交付要求：

- 本体对象支持独立dataSourceId，跨源关系明确关联键和基数，不按同名字段猜测。发布生成按数据源隔离的不可编辑Wren产物。
- QueryPlan支持有序source_steps，每步为单源结构化查询，输入引用已完成步骤的已发布关联键；禁止循环和前向引用。支持最终B结果及按唯一关联键补充A的输出列。
- 单源语义继续经Wren编译，跨源关系不能编译成单库JOIN。每源强制只读、权限、字段、超时、大小与行数门禁。
- 程序提取/去重键并绑定参数，不让模型看到中间原始数据或拼接SQL。空键集短路为正常空结果；中间结果截断、键超限、失败或键类型不兼容时明确停止，不发布不完整结论。
- Reviewer检查整体步骤计划和各步SQL。运行时绑定真实键后重新校验SQL与权限，再执行。旧审批不能授权改变后的SQL。
- 歧义澄清保留，明确方案默认自动进入SQL编译与Reviewer。人工确认/审批保留为管理员可选策略，当前演示环境使用Reviewer通过后自动执行。
- 页面展示来源、步骤、依赖、每步SQL和执行状态，展示最终结果；知识辅助、失败续聊、审计和原有单源查询继续可用。
- 使用不同实例/数据库验证A键→B查询、空结果、重复键、类型差异、敏感键、截断、失败、未授权、Reviewer退回及恢复；完成真实Docker部署验证后才标记目标完成。

实现限制必须显式呈现：保留现有1000行/10MB限制。中间取键SQL读取额外一行检测截断；不能把LIMIT 1000误当完整键集合。首版对超限键明确停止，不采用会改变聚合口径的静默分批汇总。不同源不是同一事务，说明结果的读取时间差。

首版最多8个串行步骤，每步最多依赖一个先前步骤，使用本体已发布的单键等值关系。关联键必须类型兼容且未脱敏；补充上一步字段时，该键必须唯一对应这些字段。尚不支持复合键、无上限键集、全局事务快照或任意跨源聚合表达式。

- 真实模型端到端：选择`cross_source_demo`，Analyst自主查询对象和关系，Reviewer预检提出输出清单修订并重新通过；SQL复核通过后自动执行两个独立实例。MySQL先返回100个客户分组，PostgreSQL后返回5条合成演示记录，结果补充来源记录数；金额100/200/300/400/500及每组记录数4均已与源查询核对。全程无`alignment.required`或`approval.required`事件。
- 查询最终状态`completed`，执行前与结果Reviewer均通过，返回SQL、5行结果和自然语言说明；审计哈希链有效。API重启后记录、结果、说明及私有中间结果均正确恢复，公开API不返回`source_results`和`agent_memory`。
- Docker仍运行6个MVP服务。真实浏览器验证显示两个独立SQL步骤、5行结果，无页面脚本错误；19项MVP页面测试通过，包括复核通过前隐藏跨源SQL。
