# 跨源实体选取与后续记录查询

## 修复内容

- 规划上下文按数据源列出可用字段、本地关系和跨源传递模板。跨源输入关系用于进入目标源；目标源内部可以继续沿已发布关系关联，不能把中间对象误报为缺失。
- 将“先选哪些实体”与“随后按什么指标展示”分开。按最近事件取 N 个实体必须先按实体分组并对时间取 MAX，再排序限量，不能把 N 条事件当成 N 个实体。
- 保留澄清选项的完整说明。旧会话可沿同域需求接续记录恢复已选择选项的说明；选项值改变后不继承旧解释。
- 明确重试保留需求和确认事实，重新验证候选、独立复核、编译、门禁与执行，不继承审批或旧执行结果。新需求、权限或本体变化不能直接复用旧候选。
- 具体字段错误提供路径，支持局部补丁并重新执行全部校验，避免反复重写整份方案。
- 对同方向、无条件的嵌套 MIN/MAX 预聚合采用等价折叠，保留关联类型；SUM、AVG、带条件及混合聚合不采用此优化。时间类型 MIN/MAX 不做数值 ROUND 转换。
- Reviewer 明确接收当前每步筛选、时间范围和关联键契约，不能把历史说明当成当前 SQL 的事实。

## 真实查询验收（2026-11-06）

浏览器原会话查询：按昨天完课时间选 10 个不同实体，再按已确认的全部历史录音最大时长降序展示。此处使用现有样例域，但上述实现没有按行业或表名分支。

运行 `8d251168-a52d-48ee-8f89-674b981c4805` 已完成：

| 步骤 | 返回行数 | 数据库耗时 |
| --- | ---: | ---: |
| 按最近完课时间选不同学员 | 10 | 1726 ms |
| 取得这些学员全部历史约课键 | 787 | 184 ms |
| 本地关联并取得最大录音时长 | 8 | 1384 ms |

程序核对选取键确实互异，最终结果均属于选取集合，降序正确，各步骤均未截断。后两步没有继承首步的日期与完课状态限制。最终有 8 个学员匹配到录音时长数据；没有匹配的学员不会被虚构补齐。审计哈希链验证通过。

此用例验证的是已确认的全历史范围，不代表所有新需求都应移除时间筛选。普通查询仍以其当前需求与确认口径为准。中间键上限仍为 1000 组，超过上限停止，不能静默截断。

验证产物位于本地 `artifacts/source-planning/`，不包含数据库凭据、原始文本或中间实体键。

最终重复验收运行 `f99be1a1-0cfe-4ef4-86a9-680872e6f440` 完成，端到端 42.59 秒。三步分别返回 10、787、8 行，数据库耗时 1754、103、1370 ms，均未截断，审计链有效。修订后的 Reviewer 正确区分首步选取条件与后续记录范围。

重复测试期间曾遇到一次成本估算 HTTP 超时；同一估算随后 394 ms 正常返回。现已为跨源失败补充步骤、操作和异常类型，避免空异常消息只显示“跨源查询未完成”。未增加自动无限重试或跳过成本估算。
