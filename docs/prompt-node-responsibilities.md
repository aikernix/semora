# 流程节点：任务、必要信息与产出核对

日期：2026-11-07。状态：职责审查与修改依据；已据此实现提示词重组，验证结果见 `prompt-refactor-results.md`。

已对照LangGraph流程、默认QueryIntent路径、复核/修订分支、辅助调用和兼容调用。以下描述用于决定代码与输入的删改位置，不作为一份新的长提示词发送给模型。输出为业务层面的产物定义，具体JSON编码继续使用现有契约。

## 默认问数链路

| 节点 | 要做的事 | 必须知道的信息 | 产出 |
|---|---|---|---|
| 会话与业务域绑定（程序） | 确定本次任务、可访问范围和使用的配置版本 | 用户请求、会话、业务域、身份、配置 | 任务状态、本体/配置引用、有效访问范围 |
| 对象与知识主题选择（条件性模型调用） | 从目录中挑出完成需求所需的对象和知识主题 | 当前需求、确认口径、对象/指标的简要目录 | 所需对象标识、需要补充的知识主题 |
| 资料准备（程序；需要研究时调用已有知识研究能力） | 取得所选对象定义、相关关系和知识内容 | 对象选择、业务知识缺口、现有内容与可用检索接口 | 相关语义资料、知识正文与简短引用标识、缺口/冲突状态 |
| Analyst需求理解 | 将用户意思落实为可表达的业务查询意图；识别会改变结果的未确定项 | 当前需求、本轮修改、完整确认口径、相关对象/属性/业务关系、知识内容及使用状态、必要的当前能力说明 | QueryIntent，或具体澄清问题；确有能力缺口时给出未能表达的业务目标 |
| Reviewer方案预检 | 核对候选意图是否完整、准确地表达需求 | 用户需求、确认口径、候选QueryIntent、相关业务定义；修订时增加待解决问题及本轮改动 | 通过，或具体遗漏/矛盾及验收条件，或需要用户判断的歧义 |
| 口径对齐（程序） | 展示澄清、收集答案、形成确认版本；补充文本回到Analyst | 当前草稿、已有答案、本轮补充、确认策略 | 澄清卡片、确认事实、确认需求版本 |
| 技术规划与SQL编译（程序） | 将业务意图编译为单查询或有序分步执行方案 | 确认意图、本体物理映射、关系、执行能力与权限范围 | 计划、SQL、参数、编译检查及最终输出契约 |
| SQL含义解释（单查询时的模型调用） | 用业务人员能理解的话说明这条查询如何取数 | 确认目标、实际SQL、必要字段含义及参数含义 | 简短SQL说明 |
| 门禁与成本估算（程序） | 判断SQL、访问范围和资源限制能否执行 | SQL/参数、权限、限制策略、数据库执行计划 | 门禁结论、风险、成本估算或具体连接/SQL错误 |
| Reviewer执行前复核 | 核对当前执行产物是否实现已确认口径 | 确认意图、实际执行计划与SQL、相关业务定义、适用检查结果和最终输出契约；修复时增加原问题 | 通过，或有证据的执行差异及修复验收条件 |
| 审批（程序/人工，按配置） | 对需要审批的精确查询作决定 | SQL和参数绑定、风险、访问范围、审批策略 | 与当前版本绑定的批准/拒绝决定 |
| 查询与结果合并（程序） | 按批准的计划只读执行，传递键，完成存在性筛选或再汇总 | 有效SQL/参数、依赖结果、合并契约、权限与资源限制 | 原始步骤回执、最终结果、完整性与截断信息 |
| Reviewer结果复核 | 判断实际结果是否与确认需求及执行产物一致 | 确认目标与结果粒度、最终列与结果样本、总行数、完整性信息、与判断相关的执行回执和检查证据 | 结果通过，或具体异常与可核验依据 |
| 结果说明 | 根据已复核的实际数据回答用户 | 查询目标、确认口径、列的含义、最终结果样本、总量/截断信息、解释行数变化所需的事实；需要引用时有证据标识 | 自然语言结论、数据范围和必要限制说明 |
| 审计与持久化（程序） | 保存执行和决策事实，支持回放和恢复 | 规范任务状态、版本、产物、事件 | 审计链、保存的状态、可回放记录 |

实际代码中，analyse图节点包含资料选择/准备、Analyst与方案预检等内部操作；explain图节点包含结果复核与结果说明。上述拆分以实际任务边界为准，不把每个逻辑节点都变成一个新Agent。

## 修订和继续查询

| 节点 | 要做的事 | 必须知道的信息 | 产出 |
|---|---|---|---|
| 业务意图修订（复用Analyst） | 只修正指出的业务遗漏或本轮用户改动，保留其余口径 | 原需求、确认事实、当前意图、具体问题及验收条件、本轮补充 | 修订后的QueryIntent，或确实无法决定的业务问题 |
| 技术重编译（程序） | 在业务口径不变时重建执行产物，并使旧授权按规则失效 | 当前有效意图/计划、原问题、配置及版本 | 重新生成的产物、发生的改动和检查结果 |
| 定向复核（复用当前阶段的Reviewer） | 判断原问题是否解决，并核对相关改动影响 | 原问题、验收条件、当前产物、实际改动及证据 | 关闭已解决问题，或保留具体未解决项；必要时纠正问题归属 |
| 失败后继续/下一步查询（程序分派，复用Analyst） | 判断这次补充修改了什么，并恢复必要上下文 | 当前用户消息、原需求、确认事实、上次有效意图及未完成项 | 当前任务输入；随后由Analyst输出对应的业务产物 |

技术故障的连接地址、堆栈、容器状态和重试细节属于故障处理模块。仅当它们确实改变可交付范围时，向业务分析提供简短能力状态；不让模型重新理解业务来修复网络错误。

## 独立辅助流程

| 节点 | 要做的事 | 必须知道的信息 | 产出 |
|---|---|---|---|
| 知识研究 | 根据明确的知识缺口检索、阅读和核实资料 | 知识问题、当前观察、可用检索/阅读工具及其参数 | 相关知识、支撑引用、明确的未知项和冲突 |
| 本体候选抽取 | 从证据中识别可提交审核的定义/对象/关系/指标 | 文档片段、现有定义与对象、片段引用 | 有证据支撑的候选；证据不足时保留待确认定义，不补造物理映射 |
| 模型JSON兼容测试 | 验证能否按约定返回JSON | 最小测试消息及预期结构 | 测试是否通过 |
| 模型工具兼容测试 | 验证能否调用指定工具 | 最小测试消息、测试工具定义 | 合法工具调用及测试是否通过 |

知识研究需要了解它实际使用的工具；Analyst和Reviewer只消费知识及其适用性。资料来自Wiki、文件或其他载体，不应改变同一业务定义的解释。完整来源保存在程序中，短引用可展开为原始文档、位置和版本。

## 保留的兼容流程

| 兼容节点 | 要做的事 | 必须知道的信息 | 产出 |
|---|---|---|---|
| 旧工具型Analyst | 理解需求并按旧协议形成可校验方案 | 需求/确认口径、相关目录与证据、旧协议所需的规划结构、当前问题 | 旧AnalysisPayload及已校验候选引用，或澄清 |
| 旧信息充分性判断 | 判断能否继续当前业务分析 | 当前需求与口径、已准备资料及具体缺口 | 充足/业务歧义/缺核心资料及理由 |
| 旧初步需求理解 | 判断目标是否明确、是否需要知识辅助 | 用户请求、业务域含义、知识是否可用 | 目标摘要、知识需求或澄清 |
| 旧对象选择 | 从目录选出相关对象 | 需求、对象目录 | 对象标识 |
| 旧直接JSON分析 | 按旧JSON接口形成业务方案 | 需求、确认内容、本体目录、证据、当前时间 | 原协议允许的结构化方案或澄清 |
| 旧直接执行前复核 | 核对确认需求与执行产物 | 需求、计划、SQL、门禁事实 | 原JSON复核决定 |
| 旧直接结果复核 | 核对实际结果与计划 | 计划、结果样本和统计 | 原JSON结果复核决定 |

这些旧接口需要的技术协议不能反向混入默认QueryIntent流程；本次先隔离职责与适用输入，不删除兼容能力或改变开关。

## 对照现状确认的删改点

| 现状 | 对应职责判断 | 后续调整位置 |
|---|---|---|
| Analyst提示词解释大量QueryIntent字段，包含程序拆步、MAX/MIN与候选ID生命周期等实现说明 | 需要正确表达选择/时间/汇总等业务含义；无需推演编译方法或候选权限机制 | 字段业务含义集中到Schema；编译、候选有效性继续程序控制，正文仅保留必要任务指引 |
| Wiki操作说明与资料来源细节可能跟随公共规则或知识包进入业务分析 | Analyst需要知识含义与适用状态；检索操作只属于知识研究 | 清理默认提示词和知识输入投影，完整来源保留在程序引用映射中 |
| 方案预检收到旧跨源拆步教程及较多执行产物细节 | 预检主要判断用户需求与业务意图一致性 | 移出旧SOURCE_PLANNING_RULES；必要的业务转换事实保留，技术检查归执行阶段 |
| 执行前/结果复核共用长基础段 | 前者检查执行忠实性，后者检查已返回结果和证据支持性 | 按阶段分别组装任务模板及必要输入 |
| Reviewer反复被告知不能读私有对话、不能执行SQL或决定审批 | 这些权限不由Reviewer自行决定 | 删除正文中的控制复述，保留程序隔离、工具白名单与审批实现 |
| 轮次、工具次数与Schema字段在多处重复，且预算文字已出现过时值 | 不属于业务判断 | 由实际运行策略和Schema作为唯一控制来源 |
| 全部跨源执行规则、历史修复经验无条件追加 | 仅当前确实使用的操作含义影响本次复核 | 当前操作的必要语义随结构化输入提供，错误经验以回归测试保存 |
| 复核输入重复装入需求、计划说明、旧意见，可能让已修订内容再次成为问题 | 需要当前规范版本及与本轮相关的旧问题 | 保留完整确认事实；旧产物明确历史状态，定向复核只携带必要差异及未完成项 |
| 结果说明收到偏执行协议的完整需求，而列的业务解释不一定显式提供 | 需要解释数据含义，而非了解编排实现 | 投影为确认目标、范围、输出定义和结果事实；保留原产物供审计 |
| 结果样本可能被用于推测全量完整性或前置步骤行数 | 样本只能支持有限判断 | 明确样本/总量/截断及真实回执，全量可验证检查由程序承担 |

## 后续修改的最小标准

每个模型模板只保留当前任务、所需判断和交付要求。领域定义来自输入，字段编码来自Schema，来源和权限由程序管理。需要迁出的内容应落实到实际输入或控制代码，不能仅从system删掉后假定其他地方已经覆盖。

本次审查未承诺减少节点或移除独立复核，也未假定所有模型输入都能缩成同一套字段。下一步以本表为依据逐段删改，并按已有精简计划进行行为回归。
