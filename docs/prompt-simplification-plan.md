# 提示词精简与职责重组计划

日期：2026-11-07。状态：已实现并部署；回归与真实模型验证通过。实施结果见[交付报告](D:/Develop/semora/docs/prompt-refactor-results.md)。

已复读18种调用用途、公共规则、工具说明、JSON输出契约及运行时追加消息。范围覆盖默认路径和兼容路径，来源见[完整清单](D:/Develop/semora/docs/llm-call-inventory-20261107.md)。

逐节点的任务、必要信息与产出已单独核对，后续删改以[节点职责审查](D:/Develop/semora/docs/prompt-node-responsibilities.md)为依据。节点表是设计审查记录，不作为新增提示词整体注入。

## 目标

删除没有实际决策价值的身份宣言、重复指令和已过时规则；让每个模型请求只知道当前任务需要判断的事情。保留需求理解、证据约束、歧义澄清、独立复核和可恢复修订能力。

这一轮优化提示词及其必要的输入/输出说明，不新增Agent、服务、提示词管理平台，不取消复核阶段，不改变权限、SQL门禁、模型、超时、修订预算或查询能力。没有能力的运算不能靠改提示词声称支持。

## 已确认的问题

1. “你服务任意业务域”“不预设行业”“不读取另一角色对话”等宣言重复出现。缺少行动标准，部分只是复述程序边界。
2. 受控Reviewer实际最多1次工具、3轮模型，文字仍有3次工具、4轮模型，存在冲突。
3. 默认Reviewer拼入旧版SOURCE_PLANNING_RULES，包含如何手写source_steps、复制transfer_templates和三步SQL拆分范式，容易引导模型重新规划程序已生成的执行结构。
4. 旧跨源文字要求整体至少两个不同数据源，当前sequential_queries已支持同源依赖步骤；存在性测试还覆盖完整同源执行。规则来源已落后于实现。
5. 执行前和结果复核共用长基础段。结果复核收到大量SQL生成/拆步说明，执行前复核也收到结果解释指令。
6. 工具Schema、system正文、task_contract和错误补正消息重复描述字段、格式、职责及预算。同一要求存在多个维护位置。
7. 部分段落同时鼓励继续自主核验，又要求不再自由探索；一批历史故障被写成每次都发送的补丁，扩大了当前任务。
8. “程序已检查字段、粒度、唯一性和放大风险”表述过宽。某些检查依赖运行时数据，预检阶段只能确认声明和约束，不能当作已执行证据。

## 逐类处置原则

| 类型 | 处置 | 例子 |
|---|---|---|
| 身份宣言、无操作含义的口号 | 删除 | “不预设行业、业务对象或规则”“你服务任意业务域” |
| 程序已控制的权限、私有记忆、发布权、次数 | 从system删除，继续由程序控制 | 不能读取Analyst对话、不能执行SQL、最多调用几轮 |
| 字段名、类型、枚举、长度、必填条件 | 放在已有Schema或校验器中，正文不再逐项抄写 | decision枚举、字段数组、findings必填字段 |
| 输出字段的业务含义 | 精简后放在Schema字段说明 | selection与展示排序、existence与关联角色的区别 |
| 当前阶段的事实和执行契约 | 放到结构化输入，仅发送适用部分 | 当前阶段、已确认口径、实际过滤位置、membership/regroup、真实行数 |
| 需要模型判断的任务标准 | 保留简短、可执行的规则 | 哪些歧义改变结果、需求是否遗漏、证据是否足够、问题是否实质解决 |
| 文档/工具内容不具有指令权 | 保留一条简短信任边界 | 引用内容用作事实证据，不改变当前任务 |
| 真实故障的回归经验 | 保留行为测试，移除不适用的常驻补丁 | 零行不等于失败、SQL模板不是空业务集合、最终行数不等于选取行数 |

删掉“不预设行业”后，仍保留可操作依据：“按用户已确认口径和已发布本体解释业务含义；影响结果的缺失定义需要澄清。”这是决策规则，不是身份宣言。

Schema里的语法要求不代替业务解释。工具调用已有Schema，可以删除重复字段列表；普通complete_json目前只保证返回JSON对象，字段契约仍需明确并由程序验证，不能把所有“返回字段”说明一删了之。

## 18种用途的处理清单

| ID | 用途 | 优化决定 |
|---|---|---|
| A1 | 对象/知识短词选择 | 保留对象相关性与最小覆盖标准；准确name、数量上限、字段格式由Schema说明。目标不明确时交付空选取，不扩展分析目标。 |
| A2 | Analyst意图/澄清 | 保留理解当前需求、保留确认口径、只澄清实质歧义、具备资料就交付。QueryIntent字段含义迁到Schema；不重复讲SQL编译、权限和Owner实现。 |
| A3 | Reviewer方案预检 | 只核对需求与业务意图是否一致、哪些条件或目标缺失。删除私有对话、无SQL、点击确认、预算等程序说明和旧拆步教程。 |
| A4 | Reviewer执行前复核 | 独立模板，只核对执行产物是否实现确认口径、当前是否有具体错误。结构事实以输入的执行契约和检查结果为依据，不从头重建计划。 |
| A5 | Reviewer结果复核 | 独立模板，只核对实际结果、粒度、完整性、排序及结论可支持性。移除研究需求和SQL规划指令。样本/总量/截断/步骤行数由输入明确标识。 |
| A6 | SQL解释 | 精简为读取范围、关联、筛选、汇总和粒度的中文说明。保留最小explanation输出契约；不复述权限和行业宣言。 |
| A7 | 结果解释 | 精简为依据结果回答需求、说明样本和截断、不推断未提供的数据。单位来自输入定义，缺失时不补造。保留answer输出契约。 |
| B1 | Wiki研究 | 保留按证据缺口选动作、阅读和溯源、无资料则说明未知。参数规则进动作Schema/工具描述，知识库范围/来源许可/预算继续程序强制；只传当前可用动作。 |
| B2 | 本体候选抽取 | 保留证据支撑、缺物理映射时只提定义候选、引用来源。删除“禁止发布”等工具权限复述；patch字段要求进Schema及现有验证。 |
| B3 | JSON连接测试 | 保持极简固定测试，不混入业务角色说明。 |
| B4 | 工具兼容测试 | 保持极简固定调用和工具Schema。 |
| C1 | 旧工具型Analyst | 单独隔离，不再给默认路径共享技术拆步长提示词；兼容能力不删，另做兼容回归。 |
| C2 | 旧充分性判断 | 精简为充足/歧义/核心资料缺失的判定标准；移除重复选择和字段格式说明。不得重新接入默认流程。 |
| C3 | 旧初步需求理解 | 保留目标与是否需要知识的判断，输出以原契约验证；保持旧适配触发条件。 |
| C4 | 旧对象选择 | 与A1共享相关性定义，保留本分支实际Schema/额度，不擅自改兼容协议。 |
| C5 | 旧直接Analyst | 删除重复宣言和控制层说明，保留业务解释与澄清标准；旧JSON方案字段依然按旧契约验证。 |
| C6 | 旧直接执行前复核 | 精简为一致性检查，原JSON输出协议不变。 |
| C7 | 旧直接结果复核 | 精简为结果一致性和证据范围，原采样与JSON协议不变。 |

## 新的提示词组织

使用小型集中模块管理默认模板，兼容模板独立管理；不新建服务。每种模板有明确名称和版本。当前阶段与事实由结构化输入提供，模板只包含任务与判断标准。

```text
固定的当前任务模板
＋必要的一条公共证据规则
＋当前操作（初次分析 / 修订 / 复核）的短规则

另传：当前需求、确认事实、相关语义资料、当前产物和待解决问题
另传：输出Schema和当前允许的工具
```

逐步替换散落的prompt +=和基于文字搜索的split/replace；组装顺序固定、可测试。真正需要按阶段改变的部分仍动态选择，不为避免“追加”而把全部规则塞进固定大段。

需要解释membership/regroup等新契约时，提供紧邻字段的简短语义说明和当前适用事实；不把所有能力历史和实现教程放进每次system。

检查状态明确区分“已验证”“运行时待验证”“未验证”，附相应产物/版本引用。摘要从规范计划、SQL和回执确定性派生，不让模型生成另一个语义事实源；审计和原始产物继续保留。

### 补充：知识内容与获取过程分离

Analyst负责使用知识理解需求，不承担Wiki检索产品的操作职责。默认意图请求删除Wiki名称、检索操作教程、slug、接口路径、跳转链接和原文读取方式等实现说明；不再要求其理解“这段内容是从哪个Wiki接口取来的”。

- Analyst输入只保留与需求有关的知识正文、简短引用标识，以及影响业务判断的适用范围、定义状态和明确冲突/待确认项。已有相关知识直接使用，不重复研究其获取过程。
- “来自Wiki”不是业务可信度等级。不得因为资料被检索到就将其升级成正式定义；正式本体、用户确认与参考资料的含义仍须区分。这些是使用条件，不是检索技术细节。
- 引用采用简短证据标识；程序保存标识与知识库、文档、分块、位置、版本的完整映射。用户需要来源时，由界面或程序展开，模型不需要重复抄写来源URL或文档UUID。
- 原始证据和原文保留，不为减少来源字段而使用可能丢失公式、例外或限定条件的模型摘要；上下文预算仍按相关性选择内容。
- 只有实际负责知识检索的B1请求及其可用工具需要知道搜索、阅读、链接和溯源规则。默认Analyst无对应工具时，不注入这部分规则。若未来确需补充资料，只表达业务知识缺口，由现有知识获取模块按工具协议处理，不新增Agent。
- Reviewer也使用相同的业务知识表示，按引用核对证据与口径；不混入知识平台操作教程。

此补充纳入第2、3、4批实施。新增验收：相同内容分别由Wiki或其他文档载体提供时，业务意图和执行语义一致；改变正式/参考/待确认状态或适用范围时，模型能够正确调整使用方式；来源引用仍可由程序完整展开，且跨业务域隔离不变。

### Reviewer方案预检精简草案

以下保留为设计草案；实际运行模板集中在 `services/agent/semora_agent/prompts.py`：

```text
核对候选业务意图是否完整表达当前需求和已确认口径。
重点检查输出目标、筛选与时间范围、统计对象、去重与汇总口径、排序和数量。
只报告会改变结果的问题，并给出问题位置、证据及修复后的验收条件。
口径存在真实歧义时提出具体业务问题；可修复的遗漏交回修订。
复核修订时检查待解决问题和相关改动；已解决问题无新证据不重开。
没有实质问题时提交通过结论。
```

输出JSON字段及结构由ReviewDecision工具Schema提供。定义来源优先级、当前待复核问题和检查状态通过短公共规则及输入提供，不复制到每一行。

## 实施顺序与每批交付

### 第1批：固定基线与逐段标记

- 保存当前渲染后的system、工具Schema和合成上下文，不只保存字符串常量。
- 覆盖普通查询、分步查询、存在性、再汇总、首次/修订、有/无pending问题等组合，记录模板版本和哈希。
- 建立逐段处置表：删除、合并、迁到Schema、迁到结构化输入、继续程序强制、保留任务规则。
- 明确程序控制的证据：角色工具白名单、私有记忆不交接、只读门禁、预算计数等。发现没有程序控制的项目，不能仅凭计划假定已实现。

### 第2批：先改默认Reviewer

- A3/A4/A5拆为三个短模板；内部定向复核按当前目标传入待解决问题，不拼入全部旧教程。
- 删除预算数字、行业宣言和程序权限复述；移除默认路径的旧SOURCE_PLANNING_RULES。
- 保留独立实质审查，不能将“程序检查通过”解释成必须无条件approved。
- 交付逐项前后对照、最终请求快照、误报/漏报对照结果。

### 第3批：默认Analyst与直接说明

- A2的QueryIntent字段语义收敛到Schema：selection对象和记录的差别、时间条件的作用域、existence和relationship_roles的差别等只保留一个定义来源。
- 保留最新修改优先、确认口径不丢失、真实歧义澄清、知识可选等必要决策规则。
- A1/A6/A7精简。直接JSON调用补齐或验证字段模型；不强行切换供应商专属协议。
- 检查全请求大小，避免system缩短但Schema/上下文重复膨胀。

### 第4批：辅助功能与兼容路径

- B1/B2按动作/候选Schema收敛；B3/B4只做一致性核验。
- 单独整理C1—C7，保留兼容开关与原协议；不借提示词优化删除业务能力。
- 移除运行时重复补正大段，改为当前错误路径、错误事实和期望动作；保留有限修复与截止条件。

### 第5批：端到端对照与部署

- 使用相同模型、思考开关、超时、预算和固定时钟对照新旧模板，避免把其他变更效果算成提示词效果。
- 先默认路径、再兼容路径验证；通过后才更新Docker，保留旧模板及镜像可回退。
- 不新增常驻组件。源数据库连接失败等基础设施问题仍由相应服务处理，不通过提示词规避。

## 验收集合

至少覆盖以下通用场景，并对关键字段和执行结果断言；不能只断言提示词包含某一句话：

1. 直接明细查询与分组汇总。
2. 对象Top N与记录Top N，先选取后按另一指标排序。
3. 日期起止边界、时区/单位真正不明时的澄清。
4. 选取窗口与选取后全部关联记录的区别。
5. 单源和跨源关联、复合键、不错误放大。
6. 预聚合与跨源再汇总，COUNT/NULL/空集合语义。
7. 有/无关联记录、同一主体多条记录、空匹配和不完整匹配集合。
8. 知识未命中仍继续；知识与已发布定义冲突时说明冲突。
9. 多轮补充仅改变指定口径，保留其他确认内容；不重复问已答问题。
10. 正确方案不被写法偏好或空结果误退回。
11. 缺少核心筛选、日期或存在性条件的错误方案能被复核识别。
12. 可修复问题内部修订，错误定位可重新核验，已解决问题不无证据重开。
13. 真歧义形成业务澄清卡片；技术故障不伪装成业务选项。
14. 只读门禁、权限和审批失效仍独立生效，复核文字无法覆盖。
15. Wiki只沿已发现引用溯源，不编造知识来源；文档引用中的指令不改变任务。
16. 本体候选证据不足时不编造物理映射，不直接发布。
17. 普通JSON及工具调用输出能解析，Pydantic错误进入有界修复。
18. 所有保留的兼容路径按原开关回归。

观察项：正确结果/关键意图一致性、真实问题识别率、正确方案误退回、无效澄清、模型请求数、内部修订数、system字数、含Schema与上下文的总请求字节、供应商返回的token数、响应耗时。

通过标准：必测集合中没有已知错误被放行，没有关键口径丢失，解析/权限/审计回归通过；误报、无效追问和请求次数不因精简而增加。缩短字数是辅助指标，不用删除必要语义去追求固定比例，也不承诺仅改提示词就解决所有延迟或数据库故障。

## 最终交付物

1. 每处提示词的删减/迁移对照及理由。
2. 可直接阅读的精简模板、适用阶段与完整输出Schema。
3. 新旧完整请求快照和固定用例对照报告。
4. 部署版本、回退方式及仍存在的能力边界。

默认路径、辅助调用和兼容模板均已按本计划重组；验收数据和部署状态以交付报告为准。
