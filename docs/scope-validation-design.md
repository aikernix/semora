# 数据范围验证设计边界（尚未实施）

本批不修改现有范围门禁。后续独立替换 SQL 字符串匹配，不能以提升通过率为由放行缺少授权证明的读取。

1. 从发布映射、授权快照和查询路径确定受控对象。没有 scopeField 不能推断为公共字典表；要求范围但缺少映射仍是配置缺口。公共对象要有可信授权依据。
2. 解析别名、真实表、CTE 和派生列来源，仅接受能证明归属的授权字段。对需要控制的读取路径检查；公共字典、与受控实体关联的明细不能统一套“每个叶子表都必须有独立 IN”。
3. 保守递归检查正向授权约束：AND 任一侧能证明即可，OR 两侧都须证明。NOT 自身不建立正向证明，但不能误伤同级正常业务否定。不展开 DNF；限制 AST 深度和节点数。
4. 原始绑定值必须在授权集合内；正常窄范围合法。保存占位符名称，不能使用替换成常量的解析副本核验授权值。SQL 字面量或子查询不自动视为可信绑定证明。
5. UNION 各分支与受控子查询都须有有效证明；关联或外层过滤可以在明确支持的映射规则内传播证明。递归 CTE、歧义血缘等不支持结构给出明确能力错误，不猜测放行。
6. 正反用例必须包括改名字段、窄范围、正常 NOT、OR 恒真、错误别名、另一张同名列、嵌套 CTE、UNION 缺失分支和授权变更。完整验证后再单独启用新检查。
