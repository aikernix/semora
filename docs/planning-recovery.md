# 规划失败处理（2026-11-07）

实际任务 `2798a665-0acf-4533-90bc-ee8f16ddc1f8` 请求约 84KB，已通过上下文预算。阻断原因是 QueryIntent 同时输出明细与临时聚合而没有分组，程序将其当作生成方案错误立即结束，模型未得到补正机会。

本批处理同类问题，不绑定行业、表名或字段名：

1. **可证明的程序补齐**：输出包含主体唯一标识，其他展示属性通过发布关系的对一方向取得时，明确以展示字段分组，保留逐主体粒度、原始条件与指标。没有唯一标识、含对多明细或显式分组矛盾时，不猜测分组，返回业务歧义。
2. **一次定向意图补正**：可定位的业务引用或意图错误反馈明确路径。补正时仅开放 validate_intent 与结构化提交，不开放检索、读知识或读对象。未指定条件不可修改，程序比较补正前后执行意图；重复失败结束补正。仍受既有总调用、工具次数和时间预算约束。
3. **真实歧义转澄清**：关闭工具探索，只能提交澄清问题或结论，不把未知粒度伪装为 SQL 能力问题。
4. **实际配置/能力/程序缺口**：保留候选意图及最近诊断，返回具体原因，不统一显示“请检查本体配置”，也不让业务 Analyst 编写物理 SQL 或技术步骤。不能修复的错误仍可能终止执行，不能为了降低失败数字制造结果。

失败后的新尝试交接上一份意图和具体缺口；自动补齐事实也传给 Reviewer，避免再次要求相同修正。恢复仍重新校验当前权限、本体版本及执行产物，不继承旧执行许可。

MIN/MAX 对日期、文本、布尔等非数值类型保留原始类型，不套数字 ROUND。不同字段的独立最大值不能代表同一条极值记录；当前缺少此类通用执行算子，已在能力目录明确，模型只能使用真实发布指标或说明未完成目标，不能冒充已实现。

测试覆盖逐主体明细+统计、重复关联行、字段引用补正、禁止补正时改变筛选、禁止重新检索、真实歧义卡片、非数值 MIN/MAX 以及原有编译/权限回归。此次没有开放任意 SQL、增加 Agent、放宽门禁或提高推理上限。
