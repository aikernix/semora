## 用户最新交付约束（优先于下方原始清单）

只围绕自然语言查数的核心交付与内核修改，不以做完功能清单为完成标准。验收看：需求正确落地、确认条件不丢、跨源与聚合结果正确、失败修复有效、实际端到端耗时可接受。工具Schema字节下降和Mock测试通过是辅助证据，不能代替核心交付效果。

当前只实施现有查询链路必要的上下文、最小任务状态和局部修复；先验证阶段化协议是否值得启用。成功查询库、独立索引、缓存、通用记忆平台与新UI不属于必做范围，缺少实际瓶颈证据时延期，不为完成旧清单扩功能。先完成最小内核改动，再用固定核心场景验收，修复影响交付的具体失败。下方P2/P3仅作有证据时的候选方案。

## 调整依据与共同约束

根据 WrenAI 源码调研结论更新：先识别意图、召回适用样例与相关结构，再生成方案/SQL；出错时只修复相关产物。任务拆分首先表现为同一会话负责人的阶段、状态与工具切换，不默认增加 Agent 数量，也不把确定性 DAG 节点改名为 Agent。

记忆分为两类：当前任务的结构化状态用于保留确认条件和恢复执行；历史自然语言与已验证查询配对用于检索参考。两者分别验收。WrenAI 的历史记忆主要是检索，没有证据表明其使用整段聊天的无损摘要；不以限制历史条数替代可靠的任务记忆。

版本一致性从第一批改动起适用：候选、结构检索、任务记忆、样例与缓存绑定业务域、本体内容哈希、数据源以及主体可见范围/权限版本。复用时校验当前绑定，不匹配则失效或重新验证。任何召回结果均不是执行授权，不携带旧审批或旧参数直接执行。

## 优先级与验收

1. P0：可复现评测基线。覆盖单表筛选、Top N、NULL、聚合、一对多预聚合、跨源关联、用户修正、模型超时恢复。固定需求、本体版本、数据快照、权限与模型设置；记录结果正确性、确认条件遗漏、首次工具响应耗时、总耗时、请求字节、工具 Schema 字节、模型调用数、修订数和超时率。自动测试与真实模型测量分开报告，无模型测量不得宣称提升了准确率或耗时。
2. P1：查询阶段拆分与阶段化工具协议。明确意图/歧义识别、上下文准备、方案生成、候选校验和交付的输入、输出与状态；各阶段只提供所需工具及契约，业务已明确时避免无条件增加模型调用。支持校验失败后返回必要探索，避免每次失败重做整个需求。保留完整服务端候选及最终重验、Reviewer 独立上下文、所有确定性执行门禁。用基线比较请求体、工具定义体积和模型调用数，验证每个阶段转换及失败回退。
3. P1：结构化任务记忆。存储用户已确认条件及来源、冲突、未决事项、证据引用、候选 ID、本体/数据源/权限版本。原始记录保留可回读，模型摘要不得替代用户事实。覆盖用户覆盖旧条件、否定条件、复合关联键、失败续聊、重启恢复、候选失效和证据过期。目标是减少重复上下文且条件无遗漏。
4. P1：局部错误修复。区分语义歧义、计划结构错误、编译错误、数据库执行错误和模型超时；给修复阶段当前产物、明确错误及相关定义。相同无效产物提前终止，有限重试；超时先分类诊断，不能当成 SQL 错误反复修改。语义变化重新确认，技术修复必须保持已确认口径并重新经过必要门禁。先落地已发生且可复现的错误类型，再扩大覆盖。
5. P2：已验证查询召回。只收录复核通过且执行成功的问答/方案；按主体可见范围、业务域、本体哈希、数据源筛选。召回仅作参考，重新绑定当前参数、权限和审批；定义变更失效，失败草稿不得入成功样例库。
6. P2：按规模选择结构上下文。先测量目录开销，小 Schema 在预算内完整提供，大 Schema 按名称、别名和语义召回；阈值依据请求预算与评测确定。补齐完整关联路径及键字段，允许全目录回退。对比全量结构基线，验证对象/字段召回、关系连通性以及最终结果正确性，防止只减小输入却遗漏必要关联。先实现结构选择，再视测量决定是否建设索引。
7. P3：检索与上下文缓存。在版本隔离机制已验证且有重复开销证据后实施；缓存命中与未命中必须遵循相同可见性和正确性约束，覆盖版本、权限变更后的失效验证。

推荐交付顺序：基线与版本绑定检查 → 阶段化协议 → 任务记忆 → 高频错误局部修复 → 按规模选择结构与成功查询召回 → 缓存。每批只改变一个主要变量；如基线显示结构召回遗漏或错误修复才是首要瓶颈，应基于数据调整顺序并记录原因。

## 执行方式

每次交付一个可回退的小改动，报告涉及文件、对应验证、测量值与局限，再推进下一优先级。先检查工作区已有修改，避免覆盖用户工作。不将参考源码直接引入运行依赖，不通过拉长超时、盲目截断历史、移除复核或更换模型来冒充优化。外部服务不可用时继续独立可做的实现与验证，明确真实模型未验证。

## 当前聊天的监督规则

先检查执行线程状态；运行中不重复排队催促。完成且有实质交付后审核证据，按未完成优先项发送具体工作。等待用户输入、审批或用户明确暂停时不冒充用户回答或绕过确认；报告阻塞。空闲本身不等同故障，以未完成范围和实际产物决定下一步。只在实质变化、失败或需用户操作时通知。

本文件是优化计划，不是已经创建的后台定时监控。具体任务的完成跟踪在当前聊天进行；未设置用于监视该线程的定时自动化。
