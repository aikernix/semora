# Reviewer 有界补资料与交付（2026-11-07）

本批只修改复核调用控制、补资料工具及失败后的操作建议。保留 bounded 上下文、现有阶段路由、确定性检查和审批绑定。没有更改行业语义或放宽 SQL 执行许可。

## 调用与时间预算

- 每个 run 的方案预检、执行前复核、结果复核分别计账，不互相占用机会。
- bounded 路径首次最多 3 次模型请求；后续每次定向重查最多 1 次，阶段内合计最多 4 次。相同输入最多核对两次；确实修正过的方案可以使用剩余机会，但不会重新获得预算。
- 统计真实 HTTP 尝试，网络重试也消耗机会；兼容测试适配器只有逻辑调用事件的情况。
- `REVIEW_TIMEOUT_SECONDS` 默认 120 秒，是该阶段累计运行时间，不是每次请求各 120 秒。等待人工审批的时间不计入。
- 尽力交付模式遇到无效交付不再反复修格式；完成明确的补资料动作后才允许继续请求结论。普通复核失败仍由既有 best_effort 分支转交付提示；strict 继续保留原有阻断语义。
- 显式关闭 bounded 的旧兼容路径保留原始首次 4 次模型、3 次工具上限；这不是推荐配置，本批不关闭现有开关。

## 补资料

复核已拿到相关对象的完整定义。工具只按明确的 `field_refs`、用途、影响和验收条件重取当前对象证据，不向外扩展对象或知识检索。

返回指定对象的完整定义和对象间关系后，下一轮仅开放结构化提交。缺少本体字段时返回具体缺口并关闭扩展。相同资料绑定和字段集合去重，不因改写理由再次读取。

与允许“第二批”的原计划相比，本批不额外开放一次探索：当前资料源能够一次返回所需对象完整定义，尚无第二批能补到新信息的来源。工具参数不完整时可以在剩余预算内修正；不会执行无约束的第二轮检索。

## 交付与后续范围

账号认证、权限、编译映射、模型超时和连接故障提供不同的继续操作建议；保留原始错误与已有方案。

本批未合并三个复核阶段，未改造机构范围 AST、成本估算降级、通用 JSON 宽容解析，也未修改数据契约或自动启用 best_effort。它们需要独立验证，避免一次扩大变更范围。

验收重点：真实 HTTP 重试计数、累计时间与取消、修订不重置预算、字段补齐后仅能提交、跨对象扩展禁止、换理由重复取资料去重，以及已有 strict / best_effort 查询回归。
