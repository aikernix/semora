# 跨源关联后的业务维度再汇总

2026-11-06。所有实现及新增提示词均为通用逻辑，不包含行业名称、固定表名、固定字段或业务状态码。对象、字段、主键、关系和分组完全来自当前本体及QueryIntent。

## 原因

原规划器仅能将来源主键直接映射为目标分组。用户按业务对象汇总，而实际跨源边界是该对象的一条关联记录时，直接按边界键分组会产生多行，因此旧版本选择停止。缺少的是程序的最终再汇总能力，与模型超时或缺少业务知识无关。

## 执行方式

1. 按已确认的选取条件得到不同对象；选取顺序与最终展示顺序分别保存。
2. 通过已发布关系得到边界记录主键及其所属业务维度。
3. 目标源通过参数化完整键过滤，按边界键形成未舍入的局部指标。
4. Executor核验边界键与业务维度的唯一映射；程序按最终业务维度合并SUM、COUNT、MIN、MAX。
5. 合并后排序、限量并统一格式化一次。根计划和需求版本描述最终业务粒度，局部SQL粒度只保存在source_steps中。

新增SourceQueryStep.regroup契约；包含最终分组、可合并指标、排序和限量，纳入现有候选、审批、恢复与执行绑定。原有不使用regroup的计划序列化保持兼容。Reviewer在预检及执行复核中同时得到最终输出契约，不能将局部SQL分组误认成最终业务粒度。

局部指标和再汇总都是确定性程序运算，不添加Agent或模型调用，不把中间数据交给模型计算。已授权的最终结果样本继续按原机制用于解释和复核。

## 准确性边界

- 不合并AVG、COUNT DISTINCT、任意已发布表达式或额外明细；不能直接相加平均数或局部去重数。
- 边界键必须是已发布主键，并在运行时核验维度映射唯一性；不根据字段名称猜测关系。
- 局部结果必须完整。SQL使用额外一行探测截断，超出原有行数、键数、SQL长度、超时或大小限制时停止；不能交付部分总计。
- 保留NULL和空集合语义；COUNT部分计数相加，SUM全NULL仍为NULL。
- 中间不舍入，Decimal加法按输入精度计算，最终才格式化，避免默认28位精度和局部四舍五入改变总值。
- 不在本次增加外关联补零、任意联邦查询或逐条AI分析能力。

## 验证

测试使用entity、record、fact三类通用对象，来源于两个独立合成SQLite数据库：同一对象有多条关联记录、每条记录有多个事实。单条记录局部值均小于另一对象，但合并后总值更大，验证最终排序及限量确实发生在再汇总之后。

真实模型与真实Wren联调已得到正确结果：1次Analyst、3次Reviewer、3次合成只读查询，约28秒完成。联调还发现预检上下文缺少最终输出契约、根计划仍沿用局部分组的问题，已一并修复。没有访问外部业务数据库，也没有写入生产元数据。

证据保存在artifacts/source-planning/regroup-full.xml、regroup-wren.xml、regroup-real-model.json。部署前镜像保留pre-regroup-20261106标签，无数据库DDL迁移，不新增常驻服务。

最终验收：API回归432通过、1项因未配置独立元数据测试数据库跳过；新增再汇总测试17通过；最终镜像真实Wren测试11通过。部署后六个服务运行正常，容器内关键源文件哈希与已测试代码一致，历史结果/审计读回和临时JSONB持久化往返通过。详细镜像及结果见artifacts/source-planning/regroup-result.json。

## 后续：条件作用域误拦与说明校验放宽

一次后续明细查询暴露了遗漏组合：选取条件已经在select_members执行，但继承到每个局部查询的全局说明又触发了相同条件检查，导致无筛选的后续记录展开被拒绝。这不是数据源权限不足。

- 局部查询继续做字段、类型、关系、粒度和权限检查；说明条件覆盖检查在完整方案上进行，不再要求每一步重复全局说明中的条件。
- 生产默认QueryIntent路径中，从说明文字正则识别的疑似条件差异降为explanation_filter_warnings，由独立Reviewer依据用户需求、确认口径和正式意图判断，不直接中断查询。旧手写QueryPlan兼容路径仍保留原说明覆盖规则。
- 正式QueryIntent条件采用确定性作用域覆盖检查：selection.filters必须在选取步骤执行；filters必须在后续计算执行；selection_window保留选取窗口；all_related_records不得偷偷复制仅用于选取的条件。
- 无修改数据库账号授权、只读门禁或业务域数据范围，无行业词汇和表字段特判。

新增前置条件/后续全部记录、缺失正式条件、错误复制条件、说明差异仅提示等回归。合成执行用例故意包含不满足前置条件的历史关联记录，确保对象选定后这些记录仍参加最终计算。原错误先由回归复现，修复后全套440通过、1跳过；真实模型及Wren联调结果见artifacts/source-planning/predicate-scope-real-model.json。API已更新，六个服务保持运行。回退镜像标签为semora-api:pre-predicate-scope-20261106，无DDL迁移。
