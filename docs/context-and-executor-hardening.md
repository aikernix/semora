不按行业、关键词或长度截断字段定义，不扩大预算，不增加压缩模型调用。测试逐项还原后与原上下文相等，完整保留字段含义、类型、枚举、单位及确认事实。补资料观察采用相同编码，不再突然恢复为大型字典列表。

交接诊断新增分项字节数；真正的发送前预算异常记录消息、工具契约等字节数。上下文过大仍不截断核心事实，也不会偷偷提升预算。

## 错误处理

- Reviewer 的字段引用和验收条件在工具 Schema 中必填；Analyst 保持兼容。
- 预算、阶段超时、复核输出与模型服务错误分型。best_effort 仅对明确可恢复的复核异常降级；任务失效、配置错误及意外程序缺陷不转普通建议。
- Executor 的估算和查询错误返回 `detail.error_type/db_error_code/operation/message`。MySQL 使用原生整数码，psycopg 3 使用 SQLSTATE。响应不携带原始异常、SQL、参数或凭据。
- API 对旧字符串错误、未识别响应或纯 HTTP 502 不做能力降级。只消费可信结构化类别；HTTP 成功响应仍验证数据契约。
- 单源和跨源共用估算策略：明确的估算能力缺失返回未知；连接、瞬时冲突、超时最多重试一次；认证、权限、SQL、映射问题不重试同一 SQL。
- 未知估算显示警告，不当作零或低风险。risk_based 且开启大结果审批时触发审批；disabled 仍按配置受限执行。跨源模板尚未估算与实际估算不可用分开处理。
- 正式查询不新增自动重试。错误重试耗尽后结束本次尝试、保留成果并明确继续方式，不增加没有恢复机制的等待状态。
- 对尚无修复依据的 SQL 错误保留类别、错误码和方案并明确报告，不盲目重编译相同方案；不会用估算降级绕过语法错误。

失败建议优先消费结构化类别，兼容历史错误文字补齐“无权”和数据库认证原文。建议复用仍有效的成果并重验，不能保证所有阶段都已有精确断点恢复。

## 验证边界

覆盖编码往返、完整请求预算、角色工具差异、异常白名单、原生错误码、连接有限重试、不重试正式查询、跨源未知估算交付和认证失败阻断。机构范围验证仍独立设计，本批不变更权限规则、LangGraph 递归上限或 bounded 开关。
